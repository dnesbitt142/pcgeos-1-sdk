# PC/GEOS 1.x SDK 0.1

From ChatGPT - use at your own risk!

An **experimental, community-oriented build SDK for PC/GEOS / Ensemble 1.x applications** on modern Linux and Windows hosts.

This SDK grew out of reverse engineering and reproducible builds against a GeoWorks Pro 1.2 installation. It is not an official GeoWorks SDK, it is not ABI-complete, and it does not include copyrighted GEOS system binaries. Instead, it uses a user-supplied target archive to recover exact native UI object templates and package new code into a GEOS 1.x `.GEO` executable.

## What 0.1 can do

- Compile freestanding C with **GCC/binutils on Linux** or **LLVM/Clang + LLD on Linux/Windows**.
- Produce a genuine **GEOS 1.x `.GEO`** with native kernel/UI protocol metadata and relocations.
- Create a native primary window containing a **GenView**, pointer and keyboard callbacks, application drawing, and **title-bar Help using the native 1.x help viewer controls**.
- Inspect existing `.GEO` files and scan a complete target archive.
- Reuse exact native 1.x menus, dialogs, file selectors and other controls through the advanced template techniques documented here.
- Build the included minimal Hello example. The advanced MiniCalc source shows a much larger application with spreadsheet editing, native file selectors and file I/O.

## Important limits

- The supported target for 0.1 is the exact GeoWorks Pro 1.2 build identified in `docs/TARGET_COMPATIBILITY.md` (kernel 622.3, UI 693.0).
- Generated C code requires an **80386 or newer** CPU. `-m16` is not an 8086 C memory model.
- The generic C API is deliberately small. There is no complete clone of the historical GEOS SDK headers, object compiler, resource compiler, glue/linker, or class library.
- Native UI reconstruction uses exact target object templates and must be treated as version-specific.
- The runtime scheduler/register bridge is custom experimental machinery.
- Automated tests do **not** replace a real Ensemble boot test.

## Quick start

Linux:

```sh
./bin/pcgeos1 doctor
./bin/pcgeos1 new myapp --name "My GEOS App" --permanent-name myapp --token MYA1
cd myapp
../pcgeos1-sdk-0.1/bin/pcgeos1 build project.json --gwp /path/to/GWP2.zip
```

Windows PowerShell with LLVM installed:

```powershell
.\bin\pcgeos1.ps1 doctor
.\bin\pcgeos1.ps1 new myapp --name "My GEOS App" --permanent-name myapp --token MYA1
cd myapp
..\pcgeos1-sdk-0.1\bin\pcgeos1.ps1 build project.json --gwp C:\path\to\GWP2.zip --toolchain llvm
```

Copy the generated `.GEO` into a **disposable/test** `WORLD` directory and launch it from GeoManager. Keep the original installation and a rollback path.

Start with `docs/GETTING_STARTED.md`, then read `docs/SDK_MANUAL.md`.

## Directory map

- `bin/` - command-line launchers.
- `pcgeos1/` - parser, target scanner, toolchain abstraction, UI builder and packer.
- `include/` - experimental C API.
- `runtime/` - native GEOS assembly bridge and linker script.
- `templates/basic_view/` - project generated by `pcgeos1 new`.
- `examples/hello/` - minimal example.
- `examples/minicalc/` - advanced reference source and build evidence, excluding target-proprietary binaries.
- `docs/` - full documentation.
- `tests/` - SDK self-tests.
